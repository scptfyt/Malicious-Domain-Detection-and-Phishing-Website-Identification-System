基于深度学习的恶意域名检测与钓鱼网站识别系统 设计文档

一、系统总体设计

本系统采用前后端分离架构，前端负责用户交互、检测结果展示和数据可视化，后端负责业务接口、数据管理、模型推理、模型训练调度和日志记录。系统以“数据采集与管理 -> 特征处理 -> 模型训练与评估 -> 在线检测 -> 可视化展示 -> 人工复核与持续优化”为主线，形成完整的恶意域名检测业务闭环。

推荐技术栈如下：

1. 前端：Vue 3、Vite、Element Plus、ECharts。
2. 后端：Flask、Flask-CORS、SQLAlchemy、JWT 或 Session 权限认证。
3. 数据库：MySQL。开发阶段可使用 SQLite，最终展示建议迁移到 MySQL。
4. 算法与训练：PyTorch 或 TensorFlow、scikit-learn、XGBoost、Optuna。
5. 数据处理：pandas、numpy、tldextract、python-whois。
6. 模型部署：后端加载已训练模型文件，提供 RESTful API 推理接口。

二、系统架构设计

系统分为表现层、接口层、业务层、算法层和数据层。

1. 表现层
   由 Vue 前端页面组成，包括仪表盘、单条检测、批量检测、数据集管理、模型训练、模型评估、检测历史、系统日志等页面。

2. 接口层
   由 Flask RESTful API 提供统一接口。接口负责参数校验、权限判断、异常返回、请求转发和响应封装。

3. 业务层
   处理用户管理、检测记录保存、数据集导入、训练任务管理、模型版本切换、人工复核等业务逻辑。

4. 算法层
   包含特征处理器、深度学习模型、传统机器学习模型、模型评估器和在线推理服务。输入域名或 URL 后，先解析主域名，再生成序列特征和统计特征，最后调用当前启用模型输出预测结果。

5. 数据层
   使用数据库保存用户、样本、检测记录、模型信息、训练任务、评估指标、操作日志和人工复核结果。模型权重文件保存在服务器本地模型目录中，数据库保存文件路径和版本信息。

三、功能模块设计

1. 用户与权限模块
   主要页面包括登录页、注册页、用户管理页和个人信息页。后端提供登录、退出、注册、图片验证码获取、账号注销、用户查询等接口。系统将账号分为 User 和 Administrator 两类，注册阶段仅允许创建 User 账号。普通用户仅能提交检测、查看个人历史和管理自己的模型，管理员可以查看全部用户及其使用情况。当前注册阶段不启用邮箱验证码。

2. 单条检测模块
   前端提供输入框，支持输入域名或完整 URL。后端接收请求后进行格式校验和 URL 解析，提取域名主体、顶级域名、子域名等信息。系统调用特征处理模块生成模型输入，使用当前启用模型输出恶意概率，并按阈值转换为安全、可疑、高危等级。检测完成后保存 detection_record 记录。

3. 批量检测模块
   前端支持粘贴多行文本或上传文件。后端逐条清洗输入，过滤空行和非法格式，批量调用推理流程。文件上传支持 txt、csv、tsv、json、jsonl、xlsx、xlsm、html、xml、md、log 等格式，系统通过正则提取和表格解析自动识别 URL、域名或 IP 地址。批量结果应包含原始输入、解析域名、预测标签、风险分数、风险等级和所用模型。批量检测记录可用于后续导出和复核。文件批量检测采用“先解析、再逐条检测”的前端流程，进度区展示文件解析、当前分析目标和完成数量；当识别数量超过 100 条时提示文件内容过多，并允许用户通过终止按钮取消后续检测。

4. 数据集管理模块
   支持导入正常域名、恶意域名、钓鱼 URL 和 DGA 域名数据。导入时完成去重、格式校验、标签检查和来源记录。导入方式包括文本粘贴和文件上传，文件内容可复用批量解析能力自动提取 URL、域名或 IP。管理员可以按关键词、标签和类型查询筛选样本，后续可继续扩展修改标签、删除样本和设置样本是否参与训练。

5. 特征处理模块
   字符级特征处理流程为：域名标准化 -> 字符字典映射 -> 序列截断或 Padding 至固定长度 -> Embedding 层输入。固定长度可参考 PPT 中的 255。传统统计特征包括域名长度、点号数量、连字符数量、数字比例、元音比例、信息熵、子域名数量、TLD 类型等。系统提供特征分析页面，支持用户输入 URL 后查看解析字段、统计特征和风险提示。混合模型可将深度特征和统计特征拼接后进入分类层。

6. 模型训练模块
   管理员选择训练数据、模型类型和超参数后创建训练任务。训练任务读取样本表，按比例划分训练集、验证集和测试集，执行类别权重、SMOTE 或采样策略处理数据不平衡问题。训练完成后保存模型文件、训练配置和模型版本。

7. 模型评估模块
   系统对每个模型版本保存准确率、精确率、召回率、F1 值、AUC 和混淆矩阵。前端使用表格和图表展示 CNN、LSTM、XGBoost、Transformer 或混合特征模型之间的效果对比，为论文实验章节提供支撑。

8. 模型管理模块
   系统提供模型版本管理页面，支持查看模型 ID、名称、类型、特征类型、启用状态和模型文件路径摘要。管理员可启用指定模型，也可删除无用模型；删除模型时保留检测历史，仅将检测记录中的模型引用置空。

9. 可视化仪表盘模块
   首页展示样本总数、恶意样本数、今日检测次数、高风险检测次数、当前启用模型、最近检测记录、检测标签分布、模型指标对比和风险趋势图。最近检测记录区域支持分页查看更早记录，并提供 CSV 导出入口。图表使用 ECharts 实现。

10. 检测历史与日志模块
   检测历史支持按用户、时间、风险等级、预测标签、模型版本和关键词查询，并支持分页读取和 CSV 文件导出。历史记录列表增加检测模型列，便于追溯结果来源。操作日志记录登录、退出、单条检测、批量检测、特征分析、导入数据、训练模型、启用模型、删除模型、人工复核等关键操作，便于系统管理和论文展示。系统日志页面支持按操作类型筛选日志记录。

11. 人工复核与反馈模块
    安全分析人员可对检测结果进行复核，标记为确认正确、误报、漏报或待观察。复核结果写入 review_feedback 表，并可在后续数据集扩充时转化为训练样本。

12. 管理员中心模块
    管理员可查看所有用户、各账号检测次数、复核次数、拥有模型数量，并可进入指定用户的检测记录、复核记录和模型明细页面，用于展示账号使用情况和权限隔离效果。

四、核心检测流程设计

1. 用户提交域名或 URL。
2. 后端进行输入校验，判断是否为空、是否超长、是否包含非法字符。
3. URL 解析器提取协议、主机名、主域名、子域名和路径信息。
4. 特征处理器生成字符序列特征和传统统计特征。
5. 模型推理服务加载当前启用模型，输出恶意概率。
6. 风险分级器根据概率阈值输出安全、可疑或高危。例如低于 0.4 为安全，0.4 至 0.7 为可疑，高于 0.7 为高危。最终阈值可根据实验结果调整。
7. 系统保存检测记录，并将结果返回前端。
8. 前端展示风险等级、概率、预测类别、检测时间、模型版本和解释信息。

五、模型设计

1. CNN 模型
   输入为字符 ID 序列，经 Embedding 层转换为向量后，使用多组 Conv1D 提取局部 n-gram 字符模式，再经过池化层、全连接层和 Sigmoid/Softmax 输出分类结果。CNN 适合捕捉恶意域名中的局部异常片段。

2. LSTM 模型
   输入同样为字符序列，经 Embedding 后送入 LSTM 或 BiLSTM，捕捉字符之间的长距离依赖关系。LSTM 适合处理较长域名和上下文顺序特征。

3. Transformer 模型
   使用自注意力机制对域名字符序列进行全局建模，能够学习不同字符位置之间的重要关系。该模型可作为扩展模型或创新点展示。

4. XGBoost 基线模型
   输入传统统计特征，如长度、熵值、数字比例、特殊字符数量等。该模型用于与深度学习模型进行性能对比。

5. 混合特征模型
   将深度学习模型提取的字符序列特征与传统统计特征拼接，输入分类层完成判断。该设计对应 PPT 中的“混合特征模型探索”创新点。

6. 本地训练过渡模型
   当前阶段先采用 scikit-learn 字符 TF-IDF + 分类器的方式完成本地模型训练、评估、保存和在线推理，支持字符 LR、字符 NB、字符 SGD 等轻量模型。该方案不依赖 GPU，便于本地演示和论文实验流程打通；后续在数据集和环境成熟后，可继续扩展 PyTorch 版 CNN/LSTM/Transformer 深度学习模型。

六、开发环境设计

1. 数据库环境
   本机 MySQL 数据库已部署完成，端口为 3306，账号和密码均为 `root`。后续开发、调试和演示阶段都以此数据库环境为准。

2. 数据库管理
   使用 Navicat Premium 17 进行数据库管理，包括建库建表、数据导入、表结构查看和 SQL 语句调试。

3. 编写约定
   后续毕设编写必须持续参考《需求文档.txt》和本设计文档，若新增功能或字段，优先检查是否与真实业务场景、模块数量和表数量约束一致。

4. 部署约定
   开发阶段前后端以本机回环地址联调，后端 API 默认绑定 `127.0.0.1:5000`，前端开发服务器可绑定 `127.0.0.1` 的其他端口。后续正式部署时可通过域名、HTTPS 和反向代理对外发布。

七、数据库设计

1. user 用户表
   id、username、password_hash、role、email、status、created_at、updated_at

2. domain_sample 域名样本表
   id、domain、url、label、sample_type、source、is_trainable、remark、created_at、updated_at

3. detection_record 检测记录表
   id、user_id、input_text、parsed_domain、predict_label、risk_score、risk_level、model_id、detect_time、explain_text

4. model_info 模型信息表
   id、model_name、model_type、version、file_path、feature_type、is_active、created_at、remark

5. training_task 训练任务表
   id、model_type、dataset_size、train_config、status、started_at、finished_at、created_by、log_text

6. evaluation_metric 模型评估指标表
   id、model_id、task_id、accuracy、precision_value、recall_value、f1_value、auc_value、confusion_matrix、created_at

7. feature_record 特征记录表
   id、sample_id、domain_length、entropy_value、digit_ratio、hyphen_count、dot_count、subdomain_count、sequence_length、created_at

8. operation_log 操作日志表
   id、user_id、action_type、target_type、target_id、detail、ip_address、created_at

9. review_feedback 人工复核表
   id、record_id、reviewer_id、review_result、correct_label、comment、created_at

八、接口设计

1. POST /api/auth/login：用户登录。
2. POST /api/auth/logout：用户退出。
3. GET /api/dashboard/summary：获取仪表盘统计数据。
4. POST /api/detect/single：单条域名或 URL 检测。
5. POST /api/detect/batch：批量检测，支持 JSON 文本提交和 multipart 文件上传。
6. GET /api/detect/history：分页查询检测历史。
7. GET /api/detect/history/export：导出检测历史 CSV 文件。
8. POST /api/datasets/import：导入数据集。
9. GET /api/datasets：查询样本列表。
10. PUT /api/datasets/{id}/label：修改样本标签。
11. POST /api/models/train：创建模型训练任务。
12. GET /api/models：查询模型版本列表。
13. PUT /api/models/{id}/activate：启用指定模型。
14. DELETE /api/models/{id}：删除指定模型。
15. GET /api/models/{id}/metrics：查看模型评估指标。
16. POST /api/features/analyze：分析 URL 解析结果和统计特征。
17. POST /api/reviews：提交人工复核结果。
18. GET /api/logs：查询操作日志。
19. GET /api/admin/users：管理员查看用户列表与使用统计。
20. GET /api/admin/users/{id}/detail：管理员查看指定用户的检测、复核和模型明细。

1. 登录页：账号、密码、登录按钮。
2. 仪表盘页：核心统计卡片、风险趋势图、模型指标图、最近检测记录。
3. 单条检测页：输入框、检测按钮、结果面板、风险分数、模型解释。
4. 批量检测页：文本粘贴区、文件上传、模型选择、进度可视化、终止按钮、结果表格、筛选条件。
5. 特征分析页：URL 输入、解析结果、统计特征、风险提示。
6. 数据集管理页：样本表格、导入按钮、标签筛选、来源筛选、样本编辑。
7. 模型训练页：模型类型选择、超参数配置、训练启动、任务状态。
8. 模型管理页：模型版本列表、启用模型、删除模型。
9. 模型评估页：模型版本列表、指标对比、混淆矩阵、ROC/AUC 展示。
10. 检测历史页：历史表格、详情弹窗、人工复核入口。

12. 管理员中心页：用户列表、用户统计、用户明细。

十、安全与异常设计

1. 用户密码使用哈希算法存储，不保存明文密码。
2. 后端对所有输入进行长度、格式和类型校验。
3. 文件上传限制格式为 CSV、TXT，并限制文件大小。
4. 接口按角色进行权限控制。
5. 模型推理异常、数据库异常和参数异常需返回统一错误格式。
6. 操作日志记录关键管理操作，便于问题追踪。

十一、实施顺序建议

1. 搭建后端 Flask 项目、前端 Vue 项目和数据库连接。
2. 完成数据库表结构和基础用户登录。
3. 实现单条检测流程，先用规则或已训练的简单模型打通业务链路。
4. 完成数据集管理和特征处理代码。
5. 实现 CNN/LSTM/XGBoost 训练与评估。
6. 将最优模型接入在线检测接口。
7. 完成批量检测、仪表盘、模型评估和日志页面。
8. 补充人工复核功能、完善页面样式、整理测试数据和论文实验结果。
