基于深度学习的恶意域名检测与钓鱼网站识别系统 需求文档

一、项目背景

本毕业设计题目为“基于深度学习的恶意域名检测与钓鱼网站识别系统设计与实现”。随着互联网服务普及，网络钓鱼、恶意软件传播、DGA 域名攻击等安全威胁持续增加。传统依赖黑名单、人工规则和单一统计特征的检测方法对未知恶意域名、快速变种域名和伪装钓鱼网站的识别能力有限，容易出现滞后、漏报和泛化能力不足等问题。

本系统拟将域名和 URL 视为字符序列，通过 CNN、LSTM、Transformer 等深度学习模型自动学习字符组合模式、上下文依赖和全局特征，并结合长度、熵值、数字比例、特殊字符比例、子域名数量等传统统计特征，实现恶意域名检测和钓鱼网站识别。系统需具备实际可运行的 Web 交互界面，能够支撑数据管理、模型训练、实时检测、结果可视化和日志追踪等完整业务流程。

二、建设目标

1. 构建一个贴合真实网络安全业务场景的恶意域名检测与钓鱼网站识别系统，参考 VirusTotal、Google Safe Browsing、urlscan.io、AbuseIPDB 等同类型安全检测平台的业务思路，提供域名/URL 提交、风险检测、检测解释、历史记录和统计分析等功能。
2. 建立正常域名、恶意域名、钓鱼 URL 等样本数据管理能力，支持数据清洗、去重、标注、查询和导入。
3. 实现字符级特征处理流程，将域名统一转换为模型可输入的序列特征，并支持传统统计特征提取。
4. 实现至少一种深度学习检测模型，并支持与传统机器学习模型进行对比实验。推荐实现 CNN、LSTM 和 XGBoost 基线模型；条件允许时扩展 Transformer 或混合特征模型。
5. 开发实时检测 Web 系统，用户输入域名或 URL 后，系统能够返回风险等级、恶意概率、检测类别、模型来源和辅助解释。
6. 提供可视化统计能力，展示样本分布、检测趋势、模型指标、风险等级占比、最近检测记录等信息。
7. 满足老师提出的硬性要求：功能模块不少于 5 个，数据库数据表不少于 5 张。

三、用户角色

1. 普通用户：提交域名或 URL 进行安全检测，查看检测结果、风险评分和基础解释。
2. 管理员：管理样本数据、查看检测历史、维护模型版本、查看系统统计信息。
3. 安全分析人员：进行批量检测、模型评估、结果复核、误报/漏报分析和数据标注修正。

四、业务场景

1. 用户收到可疑链接后，在系统中输入完整 URL 或域名，系统实时判断其是否存在钓鱼或恶意风险。
2. 管理员导入 Alexa Top、Majestic Million 等正常域名，以及 DGArchive、Malware Domain List 等恶意域名数据，完成清洗和标注后用于训练模型。
3. 安全分析人员对模型检测出的高风险样本进行复核，记录复核结果，便于后续优化数据集和模型。
4. 系统定期训练或手动训练检测模型，比较 CNN、LSTM、XGBoost 等模型在准确率、召回率、F1 值、AUC 等指标上的表现。
5. 系统展示检测趋势和模型效果，为毕业设计演示、论文实验分析和答辩展示提供数据支撑。

五、功能需求

1. 用户与权限模块
   支持用户登录、退出、注册、角色区分和基础权限控制。系统将账号分为 User 和 Administrator 两类，注册界面仅允许注册 User 账号。登录与注册均需进行图片验证码校验，不再使用文字算式验证码。管理员可以访问数据管理、模型训练、系统日志等功能，普通用户只能进行检测和查看自己的历史记录。

2. 域名/URL 检测模块
   支持单条域名或 URL 输入检测。系统需完成输入合法性校验、URL 解析、域名提取、特征处理、模型推理和结果返回。检测结果应包含风险等级、恶意概率、预测类别、检测时间、模型版本和简要原因。

3. 批量检测模块
   支持通过文本粘贴或文件导入的方式提交多条域名/URL。文件导入必须支持 txt 和 csv 格式，并扩展支持 tsv、json、jsonl、xlsx、xlsm、html、xml、md、log 等常见格式。系统应自动识别并提取文件中的 URL、域名或 IP 地址，批量返回检测结果，并支持按风险等级、检测类别、时间等条件筛选。为避免大文件导致浏览器长时间等待，前端应提示单次导入建议不超过 100 条，并在文件内容过多时提供可视化提醒和终止分析能力。

4. 数据集管理模块
   支持正常域名、DGA 恶意域名、钓鱼 URL 等样本的导入、查询、删除、去重、标注和复核。每条样本应记录来源、标签、创建时间、是否用于训练等信息。样本导入应支持文本粘贴和文件导入，并支持按关键词、标签和类型快速筛选样本，便于后续训练数据维护。

5. 特征处理模块
   支持字符字典映射、序列 Padding、Embedding 输入准备，以及长度、熵值、数字比例、连字符数量、子域名数量、顶级域名类型等传统统计特征计算。前端应提供特征分析页面，便于查看 URL 解析结果、统计特征和风险提示。

6. 模型训练模块
   支持 CNN、LSTM 等深度学习模型训练，并提供 XGBoost 或随机森林等传统模型作为对比基线。训练过程需支持训练集/验证集/测试集划分、超参数配置、类别权重或过采样处理、训练状态记录和模型文件保存。

7. 模型评估模块
   支持查看准确率、精确率、召回率、F1 值、AUC、混淆矩阵等指标。系统需保留不同模型、不同版本的实验记录，便于论文中进行对比分析。

8. 模型管理模块
   支持查看已有模型版本、启用指定模型、删除无用或测试模型。删除模型时需保留历史检测记录，但可将历史记录中的模型引用置空，避免误删检测业务数据。

9. 可视化统计模块
   首页或仪表盘展示系统核心数据，包括样本总量、恶意样本比例、今日检测次数、高风险检测数量、最近检测记录、模型指标对比图和检测类别分布图。最近检测记录应支持分页查看更早记录，并支持导出历史数据，方便毕业论文实验结果留档。

10. 检测历史与日志模块
   保存每次检测请求和返回结果，支持管理员查询全部记录，普通用户查询个人记录，并支持分页查询、排序、关键词搜索和 CSV 导出。历史记录中应加入检测模型列，用于追溯结果来源。系统还应记录登录、退出、单条检测、批量检测、特征分析、数据导入、模型训练、模型启用、模型删除、人工复核等关键操作日志，并支持按操作类型筛选。

11. 复核与反馈模块
    安全分析人员可对检测结果进行人工复核，标记误报、漏报或确认正确，并将复核结果作为后续数据集扩充和模型优化依据。

12. 管理员中心模块
    管理员可查看所有用户账号、各账号的检测次数、复核次数和模型数量，并可进入指定账号查看其检测记录、复核记录和自训练模型明细，用于体现账号隔离与权限管理效果。

六、开发环境与执行约定

1. 本机已部署 MySQL 数据库，端口为 3306，账号和密码均为 `root`。
2. 数据库管理工具统一使用 Navicat Premium 17，后续建库、建表、数据导入、数据查看和 SQL 调试均以该工具为准。
3. 后续开展毕设编写时，所有功能设计、表结构设计和接口设计都应优先参考本文件与《设计文档.txt》，避免遗漏老师要求的真实业务场景、功能模块数量和数据库表数量要求。
4. 系统开发阶段以本机 `127.0.0.1` 形式进行本地联调，后续部署阶段应支持绑定真实域名并通过反向代理方式对外提供服务。

七、非功能需求

1. 实用性：系统功能应贴近真实安全检测平台业务流程，不只停留在算法脚本层面。
2. 可用性：Web 页面结构清晰，检测入口明显，结果展示直观，适合答辩演示。
3. 准确性：模型应在测试集上输出可量化指标，并保存实验结果。
4. 实时性：单条检测应在较短时间内返回结果，推荐普通检测请求响应时间控制在 1 秒至 3 秒内。
5. 可扩展性：模型、特征、数据源和检测类型应便于后续扩展。
6. 安全性：用户密码应加密存储；上传文件需限制格式和大小；系统接口需进行输入校验。
7. 可追溯性：样本来源、检测记录、模型版本和训练结果应可追踪。

八、数据需求

系统数据库至少包含 5 张数据表，建议设计不少于 8 张，满足业务完整性：

1. user 用户表：保存用户账号、密码哈希、角色、状态等信息。
2. domain_sample 域名样本表：保存训练和测试用域名、标签、来源、数据集类型等信息。
3. detection_record 检测记录表：保存用户提交内容、检测结果、风险分数、模型版本和检测时间。
4. model_info 模型信息表：保存模型名称、类型、版本、文件路径、启用状态等信息。
5. training_task 训练任务表：保存训练配置、任务状态、开始时间、结束时间等信息。
6. evaluation_metric 模型评估指标表：保存 Acc、Precision、Recall、F1、AUC、混淆矩阵等指标。
7. feature_record 特征记录表：保存样本对应的统计特征和序列处理摘要。
8. operation_log 操作日志表：保存登录、导入数据、训练模型、删除记录等关键操作。
9. review_feedback 人工复核表：保存检测记录的复核结论、复核人和备注。

九、输入输出需求

1. 输入内容包括单条域名、完整 URL、批量域名/URL 文件、训练数据集文件、模型训练参数。
2. 输出内容包括风险等级、恶意概率、预测标签、检测解释、检测历史、模型评估报告和可视化图表。
3. 风险等级建议分为安全、可疑、高危三类。
4. 检测类别建议包含正常域名、DGA 恶意域名、钓鱼网站、未知风险等类型。

十、毕业设计成果要求

1. 完成一个可运行的 Web 系统，包含前端页面、后端接口、数据库和模型推理能力。
2. 完成数据预处理、模型训练、模型评估和模型部署流程。
3. 完成不少于 5 个功能模块，建议按用户权限、实时检测、批量检测、数据集管理、模型训练、模型评估、可视化统计、日志管理等模块展开。
4. 完成不少于 5 张数据库表，建议按本文档的数据需求设计 8 至 9 张表。
5. 形成可用于论文撰写的实验结果，包括模型对比、指标分析、系统功能截图和关键流程说明。
